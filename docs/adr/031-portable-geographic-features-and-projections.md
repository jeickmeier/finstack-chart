# ADR 031 — Portable geographic features and projections

Status: implementation in progress, 16 September 2026. GG15 acceptance remains open.

GG15 requires typed feature/multipart/hole data, source joins and geographic projections on native and WASM hosts without mandatory GIS runtimes, source downloads or filesystem lookup. The pinned mapproj 1.2.12 oracle contains 41 documented methods; proj4rs 0.1.10 alone has related candidates for only eleven and cannot substitute for the remaining methods.

Feature resources are owned, serializable data with exact scalar feature identifiers, explicit CRS and axis order. Ordinary dataset fields join features in chart-core, preserving source targets and the existing aesthetic/statistical pipeline. Geometry resources never require a geometry-valued interpreter object or a host preprocessing compiler. Resource size and collection nesting are bounded; malformed contours and nonfinite coordinates fail explicitly.

The source-compatible mapproj projection family is a separate concrete selection from generic registered coordinates. Its kernel implementation is immutable safe Rust using the already pinned libm dependency. It ports the original Plan 9 libmap algorithms, whose source is distributed by the Plan 9 Foundation under MIT. No C compilation, mutable global projection state or R runtime is introduced. Original source URLs and SHA-256 identities are recorded in `tools/reference/r/plan9-projection-source.json`; the full license is retained in `docs/licenses/plan9-mit.txt` and derived modules carry attribution. This does not relicense R interface changes: current oracle differences are individually qualified against independent fixtures and implemented as explicit mathematical compatibility corrections.

Primary provenance: https://9p.io/sources/plan9/LICENSE and https://plan9.io/plan9/about.html. All fourth editions were made available under MIT in March 2021. The R package itself remains a development-only Lucent Public License oracle and is not a runtime dependency.

Mapproj orientation is degrees and data-dependent when omitted. Authoring resolves the omitted orientation once into immutable definition data; runtime evaluation never inherits a previous call. Projection clipping/unprojectable outcomes and parameter behavior are being qualified against the 426-call fixture. Similar names in general-purpose CRS libraries are not aliases. Any additional CRS dependency requires its own pinned identity, license and native/WASM portability evidence before adoption.

The first resource/kernel slice does not close GG15: full projection matrix qualification, CRS transformations, geography mark integration, seams, graticules, selection, actual host replay and inspected native/publication evidence remain required.

The general CRS adapter adopts `proj4rs = 0.1.10`, license `MIT OR Apache-2.0`, with defaults disabled and only `wasm-strict` and `esri` enabled. Multithreading, binaries, logging, EPSG databases and grid resources are not enabled. The vendored manifest pins version 0.1.10; upstream crate identity and per-file hashes are retained in vendor/proj4rs/upstream-checksums.json. The prior isolated native and Node WASM Mercator spike passed; actual geographic integration remains separately gated. The adapter validates resource strings before resolving them and uses strict typed errors on every host. Geographic API tuples use degrees; internal PROJ angular tuples use radians. Two-dimensional transformations explicitly use zero ellipsoidal height.

The registry release includes unconditional WASM browser wrapper and JavaScript parser dependencies even when defaults are disabled. Therefore `vendor/proj4rs` retains upstream 0.1.10 source with a minimal core-only manifest and two portability changes: the optional browser wrapper is disabled, and numeric parsing uses Rust `FromStr` on every target. Trailing junk and integer overflow now reject identically to upstream native behavior instead of JavaScript prefix parsing. The initial patch left kernel code unchanged; the subsequently demonstrated host difference and bounded arithmetic portability patch are described below. Upstream per-file SHA-256 values and modified-file hashes are retained beside the source. Native and actual Node WASM Mercator forward/inverse spikes pass with identical anchors (`1113194.9079327357`, `5621521.486192066`); logs `/private/tmp/gg15-vendor-native-spike.log`, `/private/tmp/gg15-vendor-wasm-spike.log`, `/private/tmp/gg15-vendor-node-spike.log`. The binding CLI was explicitly 0.2.128.

The five conformal kernels additionally retain fresh-process oracle calls in `mapproj-isolated-controls.json`. The original tetra and hex C initializers multiply static arrays in place, so repeated initialization can change output. The original 426-call capture is preserved as evidence of that stateful behavior; fresh-process calls define the immutable kernel contract. All 41 families pass 318 successful calls and 108 descriptor-error cases. Full geography integration evidence remains pending. Eisenlohr uses the separately attributed d3-geo-projection4.0.0 formula, with its full ISC/additional notices in `docs/licenses/d3-geo-projection-4.0.0.txt`, normalized into source libmap units.

For redistribution we select the Apache-2.0 option explicitly offered by upstream metadata. `vendor/proj4rs/LICENSE-APACHE` retains the canonical Apache text, with its URL and SHA-256 in the patch manifest; `VENDOR-NOTICE` records the selection, upstream author/revision and local changes. Upstream source notices remain intact. The registry archive has no separate license/notice text, so no copyright attribution has been invented.

Actual geography mode2 (UTM/etmerc) produced Python/NodeWASM differences around1e-13 destination units, which propagated into panel bounds and byte-distinct SVG. Therefore the vendored implementation now routes floating transcendental methods through an internal `PortableFloat` shim backed by the already workspace-pinned `libm=0.2.16`. This mechanical change covers all28 affected projection/math/datum modules, preserving expression structure and ordinary arithmetic. No scene/output rounding is introduced. The patch manifest records every changed upstream/local hash and the new shim. Independent CRS fixtures and a fresh actual-host rerun remain the acceptance evidence for this correction.
