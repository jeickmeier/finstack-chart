## Weighted intercept quantile qualification

Executed `tools/reference/r/weighted-intercept-quantiles.R` through the same isolated runner; output `fixtures/parity/ggplot2/weighted-intercept-quantiles.json`, log `/private/tmp/gg09-intercept-capture.log`. Pinned R4.6.1/quantreg6.1, 82 cases: even/odd/tied samples, leading/trailing/interior zero weights, fractional weights, all-zero and negative rejection, singleton/constant samples; forward/reversed/interleaved permutations plus all27 three-observation integer weight vectors in both orders. Each stores five quantiles (0/.25/.5/.75/1), check-loss objectives, diagnostics, and a separately calculated lower weighted inverse candidate.

**The proposed universal lower-end tie rule is disproved.** Among74 successful fits,14 cases differ from that candidate; eight failures are expected all-zero singular designs or negative weights. For y[-1,0,3], weights[1,1,0], tau.5, pinned rq returns0 while the lower weighted inverse returns-1. Reverse order returns the same0. Equal-weight y[0,1,4,10] instead returns median1, the lower endpoint. Other exact cumulative-weight boundary cases also select an upper endpoint. Both choices minimize check loss, but produce different box hinges/notches. Therefore matching only the weighted objective does not establish source parity.

Kernel plan adjustment: intercept-only weighted boxplots need a qualified implementation of the reference rq br selection/pivot behavior (or another independently proven equivalent rule covering these counterexamples), not an unconditional cumulative-weight quantile, weighted sample expansion or arbitrary optimizer optimum. Keep this special intercept-only contract separate from the GG10 multivariate quantile solver unless a shared solver is actually qualified. All positive/nonnegative-weight inputs, zero-weight handling, selected quantiles and warnings remain testable from the committed fixtures. No runtime implementation or dependency adoption occurred in this qualification.

## Shared quantile solver route

Read-only source inspection downloaded CRAN `quantreg_6.1.tar.gz` into `/private/tmp/quantreg_6.1-source.tar.gz` (SHA256 `f42292c5ab25a15f39295b93391deafef192fe09eefde563399a64eba7e0169a`), extracted `/private/tmp/quantreg/src/rqbr.f` and inspected installed `rq.wfit`/`rq.fit.br` wrappers (`/private/tmp/gg09-rqbr-wrapper.txt`). The package declares GPL >=2; source remains external oracle evidence, not transplanted runtime code or an adopted dependency.

Weighted fitting scales design rows and responses by weight, not square-root weight, and retains zero-weight rows. The wrapper rejects negative weights and rank-deficient weighted designs; its numerical tolerance is machine epsilon^(2/3). For a fixed tau with confidence inversion disabled, the BR route is a standalone tableau solve: initialize at zero coefficients, normalize residual row signs, select entering columns and ordered minimum-ratio leaving candidates, pivot and update costs, terminate with explicit nonunique/conditioning diagnostics. The source fit route calls no separate BLAS/LAPACK/Fortran helper. Tau-path enumeration and rank-score confidence inversion are separate branches and are not required merely to implement GG09 weighted hinges or GG10 quantile prediction lines.

Owner decision: one original Rust mathematical tableau implementation will own bounded weighted quantile regression for both GG09 intercept-only boxes and GG10 general design matrices. Specify pivot/tie policies from the conceptual algorithm and independently observed fixtures, preserving input order, signed-zero/tolerance behavior where observable, rank checks, zero weights and diagnostic flags. Do not transplant the external source or adopt a copyleft runtime dependency. Do not introduce a second shortcut solver for weighted hinges. The shared kernel should accept a checked row-major design, responses, nonnegative weights and tau; return coefficients, objective, residual/dual diagnostics and convergence/nonuniqueness status with explicit memory/iteration limits. Root integration owns model/schema/public controls. Acceptance begins with all82 intercept cases, then the existing GG10 br weighted/unweighted multi-column objective/prediction fixtures; broader multivariate pivot and rank tests are required before claiming general solver parity. Other quantreg methods remain separate explicit controls, not aliases for BR.
